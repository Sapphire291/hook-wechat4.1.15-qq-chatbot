# 接入规范（聊天机器人 · 便携版）

本文件说明如何把本程序接入到一台 Windows 电脑并正常运行，以及与微信 hook、配置、数据目录、扩展接口的对接方式。

---

## 1. 运行环境

| 项目 | 要求 |
|---|---|
| 系统 | Windows 10 / 11 x64 |
| 微信 | 4.1.15.56（hook DLL 与该版本绑定） |
| 网络 | 可访问 DeepSeek API（或你配置的 OpenAI 兼容接口） |
| 磁盘 | 程序约 0.7GB（含默认表情库）；额外数据按聊天量增长 |
| 权限 | 普通用户即可；注入微信需与微信同权限（管理员启动更稳） |

## 2. 目录与可移植性

```
<部署目录>\                     ← 本副本（可整体复制到任意目录/盘符）
├─ 聊天机器人.exe
├─ _internal\
├─ config.json               ← 配置（API Key、白名单等）
├─ assets\emoji\wechat_fav\  ← 默认表情库（首次无账号库时使用）
├─ hook\                     ← 微信 hook 工具（DLL + 注入脚本）
├─ 启动.bat                  ← 一键启动机器人
└─ 代码规范.md / 接入规范.md
```

运行后自动生成（不要手动清理）：

```
memory\        # 记忆根目录（微信/QQ 完全独立）
├─ wechatMM\   # 微信记忆：memory.json、history\、hierarchy\（3 天分层总结）、summary_state.json、long_term\
├─ QQMM\       # QQ 记忆：同结构，独立计时/总结/标记/删除
└─ token_usage.jsonl  # 全局 token 统计
WID\           # 每登录一个微信账号生成 <wxid>.json 档案
EMOJE\         # 每个账号的表情库 <wxid>\wechat_fav\（md5 命名 + catalog.json）
data\          # 回复/告警记录
mod\           # 插件
```

**迁移**：把整个 `<部署目录>` 复制到别处即可继续用；数据随目录走，无需重新部署。
如需把数据与程序分离，启动前设置环境变量 `CHATBOT_HOME=<数据目录>`。

## 3. 首次启动

1. 检查 `config.json`：
   - `wechat_ai.api_key` / `base_url` / `model` 填你的模型配置；
   - `wechat_enabled=true`；如不用 QQ 可设 `qq_enabled=false`；
   - `whitelist` 配置允许回复的会话（`chat_id` 用会话显示名或 wxid）；
2. 双击 `启动.bat`（或直接运行 `聊天机器人.exe`）；
3. 程序启动后自动：
   - 读取配置、加载记忆；
   - 检测当前登录微信 `wxid`；若 `WID\<wxid>.json` 不存在 → **后台扫描该账号收藏表情**到 `EMOJE\<wxid>\wechat_fav\`（首次约 1~2 分钟）；
   - 开始按白名单/频率/安全策略回复。

## 4. 微信 hook 接入（发送能力的必要条件）

机器人通过本机 hook 进程（HTTP `127.0.0.1:30001`）发送消息；**Hook 未注入时无法发送**（但读取数据库/记忆仍可用）。

接入步骤：
1. 确认微信已安装（如 `E:\WeChat\Weixin\Weixin.exe`）；
2. 关闭已运行的微信；
3. 运行 `hook\注入Hook.bat`（自动查找 Weixin.exe 并注入 `hook\wxhook415_exp44.dll`）；
4. 微信登录后验证 hook：浏览器或命令行访问 `http://127.0.0.1:30001/Version`，返回包含 `build` 的 JSON 即成功；
5. 启动机器人。

> 说明：hook 与微信版本强绑定；微信升级后需重新匹配 DLL 版本。
> 注入脚本需要本机 Python 3.10+；若目标机无 Python，请使用你已有的注入工具完成同样操作。

## 5. 配置字段（config.json）

| 字段 | 说明 |
|---|---|
| `wechat_ai` / `qq_ai` | 各平台模型配置：`system_prompt / api_key / base_url / model` |
| `reply_style` | 回复风格 |
| `frequency_strategy` / `frequency_value` | 回复频率：interval 秒 / count 条 / mention 仅@ |
| `whitelist_enabled` / `whitelist` | 白名单：platform / chat_id / chat_name / is_group |
| `wechat_enabled` / `qq_enabled` | 平台开关 |
| `emoji_enabled` / `emoji_images_dir` | 表情开关/默认目录（账号级 EMOJE 优先） |
| `short_term_days` | 短期记忆窗口（默认 3 天；每 3 天做一级总结） |
| `short_term_max_chars` | 注入 AI 的短期记忆字符预算（默认 12000） |
| `memory_max_messages` | 分层总结的最少消息条数阈值（默认 40） |
| `wechat_screen_send` | 是否允许屏幕自动化（默认 false 更安全） |
| `voice_enabled` / `voice_asr_backend` / `voice_asr_model_dir` / `voice_cache_dir` | 语音识别（预留，默认关闭） |
| `harness_enabled` / `harness_url` / `harness_timeout` | 智能体内核（预留，默认关闭） |

## 6. 账号与表情库

- 登录账号检测：`WID\<wxid>.json` 是否已存在；
- 首次遇到新账号：自动扫描收藏表情（通过 hook 读微信进程内数据库 + CDN 明文下载 + md5 校验）；
- 多账号同机：各账号数据相互独立（`WID\`、`EMOJE\` 按 wxid 分目录）；
- 切换账号：重启机器人即可触发新账号建档/扫描。

## 7. 记忆机制（分层）

- 微信与 QQ 的记忆分别存放在 `memory\wechatMM`、`memory\QQMM`，**独立计时、独立总结、独立标记、独立删除**；
- 当前 3 天窗口的原始对话会作为短期记忆进入上下文；
- 每满 3 天：AI 总结该窗口（一级总结，权重=结束天）；
- 每 3 个同级总结（9 天）→ 上级总结（二级，权重 9/18/27…），下级移入 `archive/` 不再调用；
- 三级/四级递归；重启时从磁盘加载，**不重复调用 AI 总结**；
- `memory/token_usage.jsonl` 记录每次模型调用的 token 与缓存命中，可用于成本观测。

## 8. 扩展接口（预留）

### 语音识别（ASR）
1. 实现 `src/voice/base.py` 的 `VoiceTranscriber`（`available()` / `transcribe(audio_path)`）；
2. 在 `create_transcriber(config)` 中根据 `voice_asr_backend` 返回实现（funasr / faster_whisper / cloud）；
3. 配置 `voice_enabled=true`；语音消息的转写结果按音频 md5 缓存于 `memory/voice_cache/asr_cache.json`。

### 语音合成（TTS，预留）
实现 `VoiceSynthesizer.synthesize(text, out_path)`，并在 `create_synthesizer` 返回。

### Harness 内核（智能体旁挂）
1. 启动一个提供 `GET /health`、`POST /run`、`POST /recall` 的本地服务；
2. 配置 `harness_enabled=true`、`harness_url=http://127.0.0.1:<port>`；
3. 聊天主链路会以"检索增强"方式使用它的 `recall` 结果；复杂任务可走 `run_task`。

## 9. 常见问题

| 现象 | 处理 |
|---|---|
| 能收消息但发不出去 | hook 未注入/失效 → 重跑 `hook\注入Hook.bat`，检查 `/Version` |
| hook 突然失效（重启微信/掉登录） | 重新注入 hook；数据读取与记忆不受影响 |
| 表情库为空/不发送贴纸 | 等待首次扫描完成；检查 `EMOJE\<wxid>\wechat_fav\catalog.json` |
| 换了电脑/盘符后记忆丢失 | 迁移时复制整个目录（含 `memory\`、`WID\`、`EMOJE\`）；或设置 `CHATBOT_HOME` |
| 想清空使用痕迹 | 删除 `memory\`、`WID\`、`EMOJE\`、`data\`（本副本已不包含这些数据） |
| 想改数据目录 | 启动前设置环境变量 `CHATBOT_HOME=D:\某个目录` |

## 10. 安全提示

- `config.json` 含 API Key，请勿外发本副本；
- 本副本不含任何聊天记录/记忆/账号数据/日志；
- 语音与图片属于敏感数据，启用 ASR/视觉能力前请确认符合你的隐私要求。

## 11. 行为说明（当前版本）

- **不会自动点击登录界面**：微信未登录时只在日志提示，需要你手动扫码/点击登录（程序不抢鼠标）；
- **窗口状态**：文字发送不改变微信窗口状态（最小化下可静默发送）；贴纸/图片需要发送时微信窗口不能最小化，最小化时会跳过发送（不弹窗、不强制最小化、不恢复窗口）；已禁用屏幕自动化回退；
- **Hook 日志**：`%LOCALAPPDATA%\ChatBot\hook.log`（微信崩溃时可反馈该文件）；
- **表情包发送**：使用 hook 的「虚拟剪贴板」/SendImageVirtual2（在微信进程内伪造 OLE 剪贴板 + 程序注入 Ctrl+V，不写系统剪贴板）；微信最小化时窗口会先移到屏幕外再发送，用户看不到窗口跳出；
- **关闭程序**：关闭窗口会停止平台适配器、消息线程和QQ OneBot 连接（不会关闭你正在用的微信、QQ 本体），随后进程强制退出，不留后台；
- **稳定性**：如微信在聊天中崩溃，先重跑 hook\注入Hook.bat 再启动本程序；若仍频繁崩溃，请把 QQ OneBot 实现日志 和程序日志保留反馈排查。
