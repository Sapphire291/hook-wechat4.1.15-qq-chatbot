# 代码规范（聊天机器人 · 便携版）

本文件约定源码结构、路径、依赖、配置与打包规则。**所有新代码必须遵守**，以保证程序可整体搬迁、可维护。

---

## 1. 目录结构（源码根 `聊天机器人源码/`）

```
main.py                      # 唯一入口（GUI 启动 + 运行时装配）
config.json                  # 配置（与 exe 同级）
assets/emoji/wechat_fav/     # 默认表情库（md5 命名 + catalog.json）
src/core/                    # 基础层：paths/config/models/events/pipeline/token_stats
src/ai/                      # DeepSeek 客户端（唯一模型调用出口）
src/integration/             # 平台适配：wechat.py / qq.py / account_store.py
src/memory/                  # 记忆：MemoryStore / HistoryStore / hierarchy.py
src/emoji/                   # 表情选择与收藏表情库
src/voice/                   # 语音接口（预留：ASR / TTS）
src/harness/                 # 智能体内核接口（预留）
src/security/ src/policy/    # 安全检测 / 白名单 / 频率策略
src/ui/                      # 图形界面
src/plugins/                 # 插件机制
```

依赖锁定清单（文件 → 模块）见源码根 `代码依赖锁定.md`（自动生成，随源码维护）。

## 2. 路径规范（可移植性的核心）

1. **禁止硬编码盘符**（`E:\...`、`D:\...`、`C:\Users\...`）；
2. 所有数据路径必须经 `src/core/paths.py`：
   - `project_root()`：exe 所在目录（源码运行=源码根）；
   - `data_home()`：数据根 = 环境变量 `CHATBOT_HOME`，否则 `project_root()`；
   - `memory_dir()` / `wid_dir()` / `emoje_dir()` / `data_dir()` / `assets_dir()` / `config_path()`。
3. 运行期产生的数据目录（`memory/`、`WID/`、`EMOJE/`、`data/`、`mod/`）统一位于 `data_home()` 下，**随 exe 走**；
4. `config.json` 固定在 `project_root()/config.json`（exe 同级）；
5. 需要区分"源码运行"与"打包运行"时，用 `getattr(sys, "frozen", False)`。

> 迁移规则：`exe + _internal/ + config.json + assets/` 复制到任意目录/盘符即可运行；
> 想分离数据可在启动前设置 `CHATBOT_HOME=<数据目录>`。

## 3. 模块分层与依赖方向

```
UI(main.py / src/ui)  ──►  pipeline / adapters / generators / memory / emoji
                              │
                              ├─► src/core（paths/config/models/events）
                              ├─► src/ai（DeepSeek）
                              ├─► src/integration（微信/QQ 适配器）
                              ├─► src/memory（记忆与分层总结）
                              └─► src/voice / src/harness（预留接口）
```

- `src/core` 不依赖上层业务模块（只依赖标准库与其自身子模块）；
- `src/ai` 只做模型调用，不读写业务文件；
- `src/integration` 负责平台收发，不直接做记忆/策略；
- `pipeline` 是唯一"编排层"：白名单→频率→安全→记忆→生成→发送；
- 新增平台：实现 `ChatAdapter`（send_text/send_image/send_sticker + 拉消息），在 `create_adapters` 注册；
- 新增记忆策略：放在 `src/memory/`，通过 `MessageProcessor` 注入，不改 UI；
- 新增语音：实现 `src/voice/base.py` 的 `VoiceTranscriber/VoiceSynthesizer`，并在 `create_transcriber` 返回；
- 新增 harness：实现 `src/harness/base.py` 的 `AgentKernel`，在 `create_agent_kernel` 返回。

## 4. 配置规范

- 配置只读写 `config.json`（原子写：临时文件 + `os.replace`）；
- 新增字段必须三处同步：`AppConfig` 字段、`to_dict()`、`from_dict()`（`update_from` 视情况）；
- `from_dict` 必须带默认值，保证旧配置可直接升级；
- 敏感信息（API Key）只放 `config.json`，不得写死在代码或日志里。

## 5. 日志与产物规范

- 不在源码/发布目录堆放调试日志；调试输出用标准输出或写到 `data/` 下的日志文件；
- 发布副本不包含：`memory/`、`WID/`、`EMOJE/`、`data/`、`hook_log*.txt`、`logs/`、崩溃日志、`__pycache__`；
- 表情库、模型文件等大文件放数据目录（或 `assets/`），不要塞进 exe。

## 6. 编码规范

- Python 3.10+，UTF-8，文件头 `# -*- coding: utf-8 -*-`；
- 公共 API 必须写 docstring（中文即可），说明参数/返回/异常；
- 网络与文件 IO 必须捕获异常并降级（返回空/False），不得让异常打断消息处理线程；
- 线程安全：共享状态（记忆、缓存、统计）加锁或使用原子写；
- 不引入重量级新依赖；确需引入时写进 `requirements.txt` 并在文档说明。

## 7. 打包与发布规范

```bash
# 在源码根执行（需 PyInstaller）
python -m PyInstaller 聊天机器人.spec --noconfirm --clean
# 产物：dist/聊天机器人/聊天机器人.exe + _internal/
```

发布目录（便携版）至少包含：

```
聊天机器人.exe
_internal/
config.json
assets/                # 默认表情库（可选：账号级 EMOJE 会自动生成）
```

- 升级 exe 时保留用户数据目录（`memory/`、`WID/`、`EMOJE/`、`config.json`）；
- 发布包中不得包含开发日志、崩溃日志、测试脚本。

## 8. 提交前自检

1. `python -m py_compile` 通过；
2. 无新增绝对路径字面量；
3. `config.json` 新增字段三处同步；
4. 数据目录只经 `paths.py` 获取；
5. 发布目录无日志/记忆/账号数据残留。
