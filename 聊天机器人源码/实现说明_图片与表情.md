# 图片与表情实现说明（当前 exe）

> 适用：`E:\CHAT\聊天机器人.exe`，源码 `E:\CHAT\YUANMA\聊天机器人源码`。

## 1. 媒体目录

所有解密/下载后的可读图片：

```text
E:\data\wechat_media\
```

- 普通图片：`<wxid>_<local_id>.jpg` / `_thumb.jpg`
- 动画表情：`emoji_<md5>.jpg|png|gif|webp`
- GIF/WebP 四帧拼图：`emoji_<md5>_4f.png`

## 2. 普通图片（type 3）

代码：`src/integration/wechat.py::WeChatAdapter._to_message()`

流程：

1. 从本地解密 DB 读到图片消息（`local_type=3`）；
2. `MediaDownloader(db, save_dir=r"E:\data\wechat_media")`
   - 找到微信本机加密图片 `.dat` / `_h.dat` / `_t.dat`；
   - 用微信图片 AES 密钥解密为 JPEG/PNG/GIF；
   - 落盘到 `E:\data\wechat_media`；
3. `Message.image_paths` 带上本地路径；
4. `MessageProcessor` 调用 DeepSeek 时传 `images=...`；
5. AI 多模态读取图片内容。

## 3. 动画表情（type 47 / 11000）

### 3.1 本地缓存是加密的

微信会缓存收到的表情，但文件不是标准图片：

```text
E:\WeChatLoad\xwechat_files\<wxid>\business\emoticon\Persist\<xx>\<md5>
E:\WeChatLoad\xwechat_files\<wxid>\business\emoticon\Thumb\<xx>\<md5>.thumb
E:\WeChatLoad\xwechat_files\<wxid>\cache\<YYYY-MM>\Emoticon\<xx>\<md5>
```

实测这些文件头是随机字节（例如 `9A 8A 5F 1C...`），既不是 JPEG/PNG/GIF，也不是普通 `.dat`；
`wechatauto` 目前没有对应的表情容器解密器。

### 3.2 实际采用：emoticon.db → CDN 明图

代码：`src/integration/wechat.py::WeChatAdapter._sticker_image()`、`_make_gif_sheet()`

流程：

1. 从表情消息 XML 里取 `md5`：
   ```xml
   <msg><emoji md5="e25dd794af8a1507673eb4198e54a1ef" .../></msg>
   ```
2. 查询微信解密后的 `emoticon.db`：
   ```sql
   SELECT md5,aes_key,cdn_url,encrypt_url
   FROM kNonStoreEmoticonTable
   WHERE md5='<md5>'
   ```
   查询走 hook 只读 SQL：`POST /QueryDB/execute`，`optDbName=emoticon.db`。
3. 优先下载 `cdn_url`。实测 CDN 直接返回**明文** JPEG/PNG/GIF；
4. 若 CDN 失败，用 `encrypt_url` + `aes_key` 做 **AES-CBC**（key 同时作 IV），去 PKCS7 padding；
5. 按文件头识别格式；
6. 保存为 `E:\data\wechat_media\emoji_<md5>.*`；
7. GIF/WebP：均匀取 **4 帧**，拼成 2×2 PNG（`_4f.png`）交给多模态；
8. `Message.image_paths` 带上该图，AI 即可读取表情内容。

### 3.3 为什么不直接解本地缓存

- 本地 `business/emoticon/Persist` 是微信私有加密容器；
- 解码需要逆向容器格式/密钥，且微信升级易失效；
- CDN 路线的输入是**明文图片**，稳定、无需切聊天、无需截图；
- 代价：首次读取需要网络（之后按 md5 缓存，不重复下载）。

## 4. 发送图片/表情

代码：

- `src/integration/wechat.py::send_image()` / `send_sticker()`
- `src/integration/direct_send.py`（mode11 直发）
- `src/emoji/provider.py`（从当前 wxid 的 `EMOJE/<wxid>/wechat_fav/catalog.json` 选图）

原则：

- 不切换目标会话；

## 6. 本账号收藏表情库是怎么扫描的

代码：`src/integration/account_store.py::scan_favorites()`、
`src/emoji/wechat_fav.py`。

当前账号：`wxid_xxx`，收藏表情数量以实际扫描为准。

流程：

1. `current_wxid()` 从本地解密库/wechatauto 取当前登录 wxid；
2. 用 hook 的只读 SQL 打开微信进程内的 `emoticon.db`：
   ```text
   POST /QueryDB/execute  {optDbName:"emoticon.db", SQL:...}
   ```
3. 读取：
   - `kFavEmoticonOrderTable`：收藏顺序（md5 列表）；
   - `kNonStoreEmoticonTable`：md5、type、caption、product_id、cdn_url、thumb_url；
   - `kStoreEmoticonFilesTable`：官方表情包文件表；
   - `kStoreEmoticonCaptionsTable` / `kStoreEmoticonPackageTable`：官方描述/包名（供 `wechat_fav.py` 使用）。
4. 过滤“既没有本地文件、也没有可下载 URL”的条目；
5. 对每个 md5 用 `cdn_url`（兜底 `thumb_url`）下载腾讯 CDN 上的**明文图片**；
6. `_download_plain()` 用 md5 校验后保存为：
   ```text
   E:\CHAT\EMOJE\<wxid>\wechat_fav\<md5>.jpg/.png/.gif
   ```
7. 生成 `catalog.json`（`file`、`cdn_url`、`desc`、`tags` 等）；
8. 写入账号档案：
   ```text
   E:\CHAT\WID\<wxid>.json
   ```
   当前内容包含 `emoji_dir`、`emoji_count`、`emoji_downloaded`。

因此“本账号表情包”的权威来源是：**微信进程内 `emoticon.db`（收藏顺序+CDN 元数据）→ 腾讯 CDN 明文图 → EMOJE 账号目录**。
不是遍历微信的加密缓存文件。

补充：`wechat_fav.py` 还提供 `refresh / describe / pick` 命令；
`describe` 会调用 DeepSeek 多模态给每张表情生成一句描述和 2~4 个情绪标签，写回 `catalog.json`，
回复时再由 AI 按语境从候选里挑选。

## 7. 手动扫描聊天表情（按钮）

位置：**设置 → 表情包 → “扫描聊天表情（最近5会话×120条）”**。

代码：`src/integration/chat_stickers.py::scan_chat_stickers(session_limit=5, msg_limit=120)`。

流程：

1. 取当前登录 wxid；
2. `WeChatDB.get_sessions(limit=5)` 取最近 5 个会话；
3. 每个会话 `get_messages(limit=120)`；
4. 筛选 `动画表情 / 表情`，解析消息 XML 的 md5、cdnurl；
5. 优先用消息里的 cdnurl 下载，失败再查 `emoticon.db`；
6. 保存到：
   ```text
   E:\CHAT\EMOJE\<wxid>\chat_stickers\<md5>.<ext>
   ```
7. 合并写入 `chat_stickers\catalog.json`（`source=chat_scan`）。

特点：

- 只是下载到本地库，**不调用微信收藏接口**，微信账号里不会多出收藏；
- 与真实收藏库 `wechat_fav` 分开；
- 发送时 `EmojiProviderImpl.pick_image` 会在收藏库没有命中时尝试 `chat_stickers`；
- 实测一次扫描：5 个会话、240 条消息，发现 5 个表情，全部下载成功。

### 7.1 收到未记录表情自动保存

开关：设置 → 表情包 → “收到新表情自动保存”（默认开启，配置项
`wechat_auto_save_stickers`）。

代码：`WeChatAdapter._save_incoming_sticker()`。

流程：

1. 收到动画表情并成功下载后，取 md5；
2. 若 `EMOJE\<wxid>\chat_stickers` 没有该 md5 文件：
   - 把原图（GIF/PNG/JPG）复制进去；
   - 往 `catalog.json` 追加 `source=auto_receive` 条目；
3. 不调用微信收藏接口，不改变微信账号收藏；
4. 只写日志 `data/send_path.log`（`auto_save_sticker ...`）。

### 7.2 exe 内查看 / 预览 / 人工标注

位置：**设置 → 表情包 → 平台选择「微信」→ 刷新收藏表情**。

- 列表同时展示：
  - `wechat_fav`：真实收藏（来源标“收藏”）；
  - `chat_stickers`：扫描/自动保存/本地收藏（来源标“本地”）；
- 选中一行会显示图片预览（GIF 取首帧）；
- 「编辑描述/标签」可手动修改该表情的表达含义和标签；
  - 写入对应的 `catalog.json`；
  - 发送挑选时 `EmojiProviderImpl` 会强制重载收藏 catalog，修改立即生效；
- 默认平台已改为「微信」；QQ 仍保留原来的云端收藏列表。

### 7.3 陌生表情先下载再回复

`_sticker_image()` 的下载顺序：

1. **优先使用消息 XML 里的 `cdnurl`**（未收藏/自定义表情也能下载）；
2. 失败再查 `emoticon.db` 的 `kNonStoreEmoticonTable`；
3. 再失败用 `encrypt_url` + `aes_key` AES-CBC 解密。

下载成功后立即：

- 加进 `image_paths` 供 AI 识别；
- 若本地库没有该 md5，`_save_incoming_sticker()` 先保存到 `chat_stickers`；
- 然后才把消息交给主流程生成回复。

### 7.4 GIF/WebP 的语义提示

GIF/WebP 传给多模态的是 4 帧 2×2 拼图，但消息内容会写成：

```text
[GIF表情包：下面是同一动画的4帧拼图（左上、右上、左下、右下），不是普通四格图片]
```

这样模型知道这是同一动画的连续 4 帧，而不是四张不同图片拼在一起。
静态表情仍用 `[表情包]`。

### 7.5 平台启停按钮

微信/QQ 的「启动/停止」按钮从主窗口底部移到了：

```text
设置页 → 最底部 → 保存设置上方
```

这一行固定在设置页底部，窗口变小时仍可见；设置页内容本身仍可滚轮滚动。

### 7.6 登录自动扫描收藏表情

`WeChatAdapter._login_watchdog()`：

- 每 8 秒查 `/QueryDB/status` 的 `IsLogin`；
- 首次检测到已登录（程序启动时已登录也算）或 `0 → 1`：
  - 自动调用 `account_store.scan_favorites(wxid)`；
  - 下载/更新 `EMOJE/<wxid>/wechat_fav` 与 `catalog.json`；
  - 日志：`data/account_scan.log`；
- 后台线程执行，不弹提示框。

### 7.7 微信最小化时锁键鼠

开关：设置 → 回复设置 → “微信最小化时锁定物理键鼠”（默认开启）。

代码：`src/integration/input_guard.py`。

规则：

- 仅当微信主窗口 `IsIconic`（最小化）时阻断；
- 本程序窗口在前台时不阻断（还能操作聊天机器人）；
- `Ctrl+Alt+Shift+U` 临时解锁 30 秒；
- 取消勾选并保存即可关闭；
- 日志：`data/input_guard.log`。

## 8. 当前限制

1. 表情依赖 `emoticon.db` 的 `kNonStoreEmoticonTable`；
   自定义/商店表情如果不在该表，可能退回 `[表情包]` 标记；
   （可后续补 `kStoreEmoticonFilesTable` / `kCustomEmoticonOrderTable`）
2. CDN URL 可能过期，但同一 md5 已缓存到 `E:\data\wechat_media`，不会重复下载；
3. 动画表情的本地加密容器未解密；读取的是 CDN 明图，不是改写微信缓存。
